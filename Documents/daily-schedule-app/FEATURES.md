# Scram（滚蛋计划）- 功能清单与版本规划

## 版本总览

| 版本 | 定位 | 核心内容 | 预计周期 |
|------|------|----------|----------|
| **V1 MVP** | 个人使用（一人公司） | 项目管理、里程碑、子任务、AI拆解、Markdown导入、打卡、自动延期、吐槽系统、周结算 SSS 评级、推送通知 | Week 1-4 |
| **V2 多人协作** | 小规模工作室（3-5人） | 项目协作组、互相吐槽、团队周排名、共同子任务、可见性控制 | Week 5-8 |
| **V3 AI 增强** | 智能增强 | AI 智能时间分配、延期智能分析、AI 周报、AI 吐槽文案 | Week 9-12 |

## 吐槽模板引擎设计（MVP 方案）

吐槽采用 **模板 + 任务上下文** 方式，无需 AI 即可做到"结合实际任务"的个性化吐槽：

```
吐槽文案 = 模板(任务名称, 延期次数, 时间段, 历史完成率, 任务类型标签, 所属项目)
```

### 任务类型标签映射

| 关键词 | 标签 | 糖果色 |
|--------|------|--------|
| 产品 / 设计 / 评审 / 规划 | 产品设计 | 粉红 |
| 编码 / 写代码 / coding / 开发 | 写代码 | 天蓝 |
| 测试 / 修复 / bug | 测试修复 | 金黄 |
| 文档 / 报告 / 写 | 文书 | 薰衣草紫 |
| 会议 / 沟通 / 汇报 | 社交 | 薄荷绿 |
| 学习 / 课程 / 读书 | 学习 | 珊瑚橙 |
| 其他 | 不知道什么鬼 | 灰色 |

### 模板示例

```
"「{任务名称}」延期{N}次了，{时间段}的任务硬生生拖成了连续剧"
→ "「产品设计」延期3次了，10-12点的任务硬生生拖成了连续剧"

"「{项目名}」的{任务名称}都延了{N}次了，项目进度被你自己拖慢了"
→ "「日历APP」的「产品设计」都延了4次了，项目进度被你自己拖慢了"

"「{任务名称}」{历史完成率}%的完成率，说实话这个任务对你来说是不是超纲了"
→ "「前端重构」25%的完成率，说实话这个任务对你来说是不是超纲了"
```

- 每种级别预置 15-25 条模板
- 同一文案 3 天内不重复
- **V3 可切换为 AI 动态生成**

## Markdown 导入格式规范

### 支持的文件格式

```markdown
# 项目名称

## 里程碑1：产品设计（第1周）
- 周一 10:00-12:00 需求分析
- 周二 10:00-12:00 交互设计
- 周三 10:00-12:00 视觉设计

## 里程碑2：前端开发（第2-3周）
- 周一~周五 10:00-12:00 首页开发（循环）
- 周一~周五 14:00-16:00 打卡功能开发（循环）

## 里程碑3：测试上线（第4周）
- 周一 10:00-12:00 功能测试
- 周三 10:00-12:00 Bug 修复
- 周五 10:00-12:00 App Store 提交
```

### 解析规则

| 格式 | 解析结果 |
|------|----------|
| `# 项目名称` | 项目名称（可选，通常已在项目中指定） |
| `## 里程碑X：名称（第N周）` | 创建里程碑，目标日期为第N周周五 |
| `- 周X HH:MM-HH:MM 任务名称` | 创建子任务，重复规则为自定义周X |
| `- 周X~周Y HH:MM-HH:MM 任务名称（循环）` | 创建循环子任务，重复规则为自定义周X~周Y |
| `- 周X HH:MM-HH:MM 任务名称` | 创建一次性子任务，重复规则为一次性 |
